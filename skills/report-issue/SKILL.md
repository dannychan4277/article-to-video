# 回報問題

作者遇到做不出來、或做出來不對的狀況，想交給 Danny（這個外掛的維護者）處理。
你要做的只有一件事：打包一個 zip 放到桌面，告訴作者怎麼傳給 Danny。
不要自己動手修，也不要叫作者去終端機打指令。

## 步驟

1. **確定是哪個專案。** 通常就是這次對話正在做的那支影片的專案資料夾（裡面有 narration.json 和 shots.json）。
   每支片在「影片」→「解說影片」裡有一個「日期-片名」資料夾，專案資料夾是它裡面的「專案」；
   不確定是哪一支，找最近的那個，跟作者確認片名。安裝測試片出問題時，專案資料夾就是「安裝測試片」本身。
   完全沒有專案也能回報（例如安裝就出錯了）：指令不要帶專案資料夾。

2. **寫一句問題描述。** 用作者的話寫，例如「第 3 張圖的柱子高度不對」「按做片之後卡住不動」。
   這次對話裡看過的錯誤訊息，摘一兩句放進去。

3. **找出是哪個分鏡出錯。** 作者講了「第幾張」，或錯誤訊息裡點名了「分鏡 SH03」，就用 `--shot` 帶上
   （寫編號 3 或寫 SH03 都可以，有好幾個就帶好幾次）。不知道就不要帶，程式會從最後一次做片的錯誤自己找。

4. **打包。** 跑這一行（路徑和描述都要加引號）：

   ```
   uv run --project ${CLAUDE_PLUGIN_ROOT} python -m article_to_video report-issue "<專案資料夾>" --shot 3 --note "<問題描述>"
   ```

   它會順便渲幾張出錯分鏡的畫面，大約十幾秒。就算畫面渲不出來（那可能正是問題所在），zip 還是會做好。
   說找不到 `uv`：把開頭的 `uv` 換成 `~/.local/bin/uv` 再跑一次。

5. **告訴作者。** 用口語講，大意是：
   - 檔案已經放在桌面，檔名是「回報問題-….zip」（照抄指令印出來的檔名）。
   - 打開 LINE 跟 Danny 的對話，把這個檔案拖進去傳出去就好，不用解壓縮、不用改名。
   - 裡面有什麼：照指令印出來的「裡面有」那行講。
   - 沒放什麼：文章全文、成片、配音檔都沒放；檔案路徑裡的使用者名稱也遮掉了。
   - 指令有印「注意：…」的話，用白話轉述給作者聽。

## 出狀況時

- 指令本身失敗（印出「打包失敗」，或一大段英文錯誤）：請作者把這段對話的畫面截圖，用 LINE 傳給 Danny。
- 作者其實是想知道哪裡錯、想自己改：那不是回報，回到做片的流程處理。
