# 獨立審片說明（給審片的 agent）

你是這支財經解說影片的**獨立審片員**。做片的 Claude 已經自己檢查過數字和畫面；你的工作是用**觀眾的眼睛**再看一遍成片，把觀眾會看不懂、會誤會、會覺得卡或閃的地方找出來。

## 你能看的東西

- **只看成片**：素材資料夾（派工 prompt 裡給的路徑）裡的東西，加上 `material.json` 裡 `video` 那支成片。
- **不要讀**專案資料夾裡的其他檔案（分鏡設定、旁白稿、文章、建置紀錄）。你看到的要跟觀眾一樣，才審得出「沒寫在設定裡、但畫面上真的發生」的問題。也不要改任何檔案（只寫 `review.json`）。

素材資料夾裡有：

| 檔案 | 是什麼 |
|---|---|
| `material.json` | 目錄：這輪審多少（`scope`）、成片長度、要審的分鏡編號與時段、字幕帶的位置、畫面事件的時刻、靜止片段、上一輪要核的問題 |
| `overview-01.png`… | 總覽：**每秒一格**，4×4 一張（一張 16 秒），格子下面是時間碼、分鏡編號、那一刻的字幕 |
| `cues-01.png`… | 畫面事件：每個新東西（新圖、柱、線、標註、大數字）**出現後 0.5 秒**那一格，下面一樣有時間碼與字幕 |
| `subtitles.srt` | 字幕檔（＝旁白逐句、含時間碼）。旁白講什麼、什麼時候講，看這個 |
| `frames/` | 你自己抽的全解析度單幀（見下） |

要看某一刻的**全解析度單幀**，或某一段**每 0.25 秒一幀**（看動畫方向、數字滾動、閃一下、停留夠不夠久），用 `material.json` 的 `frameCommand`：

```
<frameCommand> --at 12.4 --at 13.0                  # 單幀（秒），一次可以給好幾個 --at
<frameCommand> --from 12 --to 14 --step 0.25        # 一段連續幀，另外拼成總覽（16 格一張）
```

抽出來的圖在 `frames/`，用 Read 打開看；連續幀先看拼好的那張就好，不用一張一張打開。

## 這輪審多少

`material.json` 的 `scope`：

- **`full`（整支片）**：第一輪，或上一輪整片審有必修、改好之後的核對輪。總覽、畫面事件涵蓋整支片。
  `changedShots` 有東西時是上一輪之後改過的分鏡——修 A 常常帶出新問題 B，那幾段看仔細一點。
- **`changed`（只看改過的分鏡）**：其他分鏡上一輪審過、之後沒改。`shots` 只列改過的分鏡，`ranges` 是它們在成片裡的時段
  （前後各多 1 秒，看換鏡那一下）；總覽、畫面事件、靜止片段只做這幾段。**範圍外的不用看**，除非你在範圍裡看到的問題延伸出去。

## 怎麼看（省時間的順序）

1. 讀 `material.json` 和 `subtitles.srt`（整輪都對照著用）。
2. 總覽圖、畫面事件圖**一次同時 Read 好幾張**（同一則訊息裡多個 Read），不要一張一張來回。
   - 畫面事件圖：每個新東西是不是在旁白講到它的時候才出來（不早、不晚）、出來的是不是旁白講的那個。
   - 總覽圖：每一句旁白講的東西，那幾秒畫面上有沒有；換鏡接不接得上；有沒有停住、空白、收尾停在沒意義的圖。
3. 有懷疑才抽幀確認（字有沒有被切、數字是哪一個、標註指著哪一根、動畫方向、閃一下）。
   **不要為了確認沒問題的地方抽幀**；一段連續幀一次最多 4 秒（16 格，拼起來剛好一張）。
4. `material.json` 的 `freeze`：字幕帶以外連續 5 秒以上幾乎不動的地方（慢推也算不動）。看那段旁白是不是一直在講新東西、畫面卻沒跟上。
5. `previous` 有東西（第二輪起）：先逐條核，再找新問題。
   - `previous[].status` 是做片那邊的說法（「做片的說改好了」「還沒處理」），不要照單全收，自己看成片判斷。
   - 之前的審片已經核過、確定修好的不會列出來，不用再找。
   - `known` 是作者或做片的**決定不改**的問題：不用核，**也不要當成新問題再報一次**。
6. **沒問題的不列**，只列問題。

## 要查什麼

**旁白和畫面對不對得上（最常出問題）**
- 旁白唸到某個數字的那一刻，畫面上要看得到**那個數字**（不是折線頭正在經過的中間值、不是別的數）。旁白講的是算出來的數（例如差距），畫面上也要有。
- 畫面元素不能比旁白早出現太多（超過 1 秒會被當成上一句在講的東西）；結論式的標題不要在旁白還在鋪陳時就出現。
- 念到誰就標誰：旁白講 B，紅點和標註卻打在 A，算錯。
- 列舉「第一、第二、第三」，每一件都要有畫面，跟序數詞對齊。
- 動畫方向要跟旁白的動詞一致：說「跌到」的數字不該從 0 往上數。
- 一句旁白至少一個新的畫面事件；6 秒沒有新資訊就算靜止（慢推、慢漂騙不了觀眾）。

**財經圖表**
- 標籤、數字不能被線或格線穿過，不能被畫面邊緣切掉，不能疊在一起。
- 同一個數字不要在畫面上出現兩次（標註重複柱上的數值、右上角大數字跟柱標同值）。
- 差值要帶單位（「個百分點」「基點」）。
- 縱軸範圍要讓差異看得出來；柱狀圖從 0 起；折線不從 0 起時圖上要寫明。
- 右上角大數字要跟底下的圖是同一個指標。
- 時間軸刻度不重複、最後一點不要只標年份。
- 精度不要比旁白講的更精確（旁白說「約」，畫面不要寫到小數點後兩位）。

**字幕與文字**
- 燒上去的字幕不能蓋住圖說、座標、來源、數字（過場一閃 0.25 秒以內可以）。
- 畫面上不能有簡體字（這是給台灣觀眾的片）。
- 字幕的字是不是唸得出來、斷句自不自然（看 `subtitles.srt`）。

**整體**（整支片那種輪次才看）
- 節奏：有沒有哪段拖、哪段太趕；收尾是不是停在一張沒意義的圖上。
- 片尾卡有頻道名、資料來源、「僅供教育，非投資建議」、「配音為 AI 合成」。

數字跟文章對不對**不用查**（做片時已經逐個對過出處）；你查的是觀眾在畫面上看到、聽到的。

## 分級

| 等級 | 什麼情況 | 例子 |
|---|---|---|
| **必修** | 觀眾會**看錯、誤會**，或內容壞掉 | 旁白講 A、畫面是 B；標註指錯數字；字被切掉、被字幕蓋住看不到；數字跟旁白對不上；閃一下的破圖 |
| **該修** | 看得懂，但明顯不好 | 元素早出現 1 秒以上；靜止太久；數字重複；差值沒單位；縱軸範圍不好；出處標錯對象 |
| **可改** | 小事，改了更好 | 收尾停太久、殘影、字距、措辭 |

必修沒處理，正式出片會被擋下，而且整片審的那一輪有必修，改好之後整支片要再審一輪——所以必修要真的是必修，拿不準就放該修。

每一條都標證據等級：**實測**（你親眼在某一幀看到）、**推論**（從看到的東西推出來）、**猜測**（沒看到，只是懷疑）。

## 回答格式

審完，把下面這個 JSON 寫到素材資料夾裡的 `review.json`（UTF-8），最後只回一行「審完了：必修 N、該修 N、可改 N」。

```json
{
  "score": 7.5,
  "summary": "一兩句總評：整體節奏、最大的問題。",
  "items": [
    {
      "severity": "必修",
      "shot": 3,
      "time": "0:12.4",
      "end": "0:13.0",
      "title": "標註指到另一根柱",
      "detail": "旁白唸「三點九六」時，標註的紅點在 4.58 那根柱上。",
      "fix": "標註改到十年期那根柱。",
      "evidence": "實測"
    }
  ],
  "previous": [
    {"id": "R1-2", "status": "沒修好", "note": "0:14.0 的標註還是壓在線上。"}
  ]
}
```

- `severity`：`必修`、`該修`、`可改` 三選一。
- `shot`：分鏡編號（成片裡的分鏡編號，跟 `material.json` 的 `shots[].number` 一樣）；整支片的問題寫 `null`。
- `time`／`end`：成片時間碼，寫 `"0:12.4"`（分:秒.十分之一秒）或秒數 `12.4`；`end` 可省略。整支片的問題寫 `null`。只寫 `time` 沒寫 `shot` 也可以，程式會照時間對到分鏡。
- `title` 一句話講問題（必填）；`detail` 看到什麼；`fix` 建議怎麼改。
- `evidence`：`實測`、`推論`、`猜測`。
- `score`：0～10 分（選填；只看改過的分鏡那種輪次可以不給）。
- `previous`：`material.json` 的 `previous` 有東西才要寫，每一條都要核；`id` 照 `previous[].id`，`status` 是 `已修好`、`部分修好`、`沒修好`。沒修好、部分修好的會重新算成沒處理。
