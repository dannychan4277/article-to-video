# 自動檢查與獨立審片（主 skill 照這份做）

作者第一次打開審片頁之前，這三件事都要做完：**自動檢查**（qa＋字幕帶）、**獨立審片**一輪、處理查出來的**必修**。作者不該當除錯員。

指令一律 `uv run --project ${CLAUDE_PLUGIN_ROOT} python -m article_to_video <子指令> …`，下面省略前綴。直式（9:16）的片每個指令都加 `--aspect 9:16`。

## 順序

1. `build <專案>`：建置成片（數字對帳對不上會擋在這裡）。這份成片留在專案資料夾給審片用，
   **還不是出片**：作者點頭之後 `publish` 才把成片放進「影片／解說影片／日期-標題」。成功時會印「下一步」。
   還有沒處理的必修時 build **照樣跑**，最後列出「還有 N 項必修還沒處理」：改了分鏡就是要重建來驗證。擋的只有 `publish`。
2. `checks <專案>`：自動檢查。每個片段跑 qa、白底片段查字幕帶，結果印出來、寫進審片頁。片段沒變的用快取，改一個分鏡只重查那一個。
3. 處理 checks 的結果（見下）。改了分鏡就先 `preview` 看改到的靜態圖，再回到 1。
4. 獨立審片（使用者設定 `independent_review` 開著才做；`settings show --json` 看）：
   1. `review-prep <專案>`：照「再審幾輪、審哪些」的規則自己選這輪審**整支片**還是**只看改過的分鏡**（印「為什麼…」），
      從成片準備素材，印出 prompt 檔路徑。
   2. 用 Agent 工具派一個 agent，prompt 就是 `prompt.txt` 的全文。它要能跑 Bash（抽幀）和 Read（看圖）。只給它 prompt——它只看成片才有意義。
   3. agent 寫好素材資料夾裡的 `review.json` 後：`review-record <專案>`。格式不對會列出哪一項錯，請 agent 改好再記。
5. 處理審片的問題（見下），再照「再審幾輪、審哪些」決定要不要再審。改了分鏡就回到 3（先 `preview` 看改到的靜態圖、再 build、checks）。
6. 都處理完：`open-review <專案>` 打開審片頁給作者看（`build`、`checks`、`review-record` 也都會更新審片頁）。
   打開給作者看才算一版：前面 `--no-open` 的預覽、建置和檢查都不加版，作者第一次看到的就是第 1 版。
7. 作者留言要改的：改 → `preview`（只重渲改到的分鏡）→ `open-review`，不用每次重做整支片、也不用每次重審。
   改得很多（約三分之一以上的分鏡，或整段旁白重寫）才再走一次 1–5，這時審片只看改過的分鏡。
8. 作者點頭：`publish <專案> --version <他看的那一版>`。它會再建置一次（沒改的片段用快取）、
   自動檢查這次新渲的片段，有沒處理的必修照樣擋；這支片如果一輪獨立審片都沒做過（設定開著時）也擋。

## checks 的結果怎麼看

每個分鏡一行：✓ 沒問題、! 該修、✗ 有必修沒處理、? 還沒檢查。有問題的下面列出檢查項目、時間碼、說明、代號，和對照圖（四幀＋運動熱圖，`build/<比例>/checks/qa/<片段>/<片段>.jpg`）。`--json` 或 `build/<比例>/checks.json` 有全部數字。

| 檢查 | 是什麼 | 通常怎麼修 |
|---|---|---|
| 動態 | 慢推（`camera: slow`）：圖表幾乎沒在動（沒慢推、畫完就停）。快推（預設）：停住是故意的，不看整段；看分鏡設定寫的每個畫面事件那一刻——該長出東西，畫面卻幾乎沒變＝沒畫出來（訊息會寫是哪種事件） | 慢推：不要寫 `"push": 0`；或把這段拆短。快推：看對照圖那一刻；同一個分鏡寫了兩個沒寫 `data.index` 的 bar cue，只有第一個會長柱子（刪掉多的，或寫 `data.index`）；看不出原因就回報問題 |
| 跳變 | 一幀裡突然變了一大塊（閃一下）。快推的那 0.3 秒照分鏡設定裡的時刻放過，其他時間照查 | cue 的 `dur` 太短（例如柱子一幀長完）；拿掉 `dur` |
| 半截字、疊字 | 字被畫面邊緣切掉、兩串字疊在一起 | 推近太多（`push` 調小）、標題或標註太長 |
| 字進字幕帶、字幕帶 | 字或圖壓進燒字幕的那一條 | 推近太多、圖區塞太多東西 |
| 近空白 | 整個畫面幾乎是空的 | 第一個 cue 太晚 |
| 停太久（該修） | 旁白期間超過 5 秒沒有新畫面 | 一句旁白配一個新事件；或拆成兩個分鏡 |
| 確定性、頁面報錯 | 引擎每次渲得不一樣、或報錯 | 回報問題（`report-issue`）給 Danny |

**必修一定要先看對照圖再決定**：真的有問題就改分鏡設定、再 build、checks（片段改了會自動重查，不用標）；確定沒問題（例如這裡本來就要一次跳出來）才接受：

```
resolve <專案> qa:SH03:jump@1a2b3c4d --accept "理由"
```

## 獨立審片的必修怎麼處理

- 改得到的就改：改 → `build`（必修還開著也會跑）→ 看過成片或抽幀確認改好了，才記下：`resolve <專案> R1-2 --fixed "怎麼改的"`。
  不要為了讓 build 跑而先記「改好了」。
- 你判斷不用改的，**要問作者**；作者說不改才記：`resolve <專案> R1-2 --accept "作者說…" --by 作者`。不要自己替作者接受審片的必修。
- 該修、可改不擋出片，挑值得改的改；審片頁上作者都看得到（卡上只攤開最新一輪的可改，較早幾輪還開著的收成一行「較早幾輪還有 N 項可改」，沒人重新核對、可能已經過時——改分鏡時順手看一下還成不成立）。
- 下一輪審片如果說某一項「沒修好」或「部分修好」，那一項會重新變成沒處理。

## 再審幾輪、審哪些

示範片（2 分鐘）整支片審三輪花了 28 分鐘，第三輪沒找到任何必修。所以只在有必修要核對時才再審，而且盡量只看改過的分鏡：

| 上一輪審完 | 改好之後 |
|---|---|
| 整支片審的那一輪**有必修** | build → checks → **整支片再審一輪**核對（必修改動大、也最容易帶出新問題）。整支片最多審 **2 輪**。 |
| 整支片已經審了 2 輪，還有必修 | build → checks → 再審一輪，**只看改過的分鏡**。 |
| **沒有必修**（或必修都已經被審片核過） | **不再派審片員**。值得改的該修改掉 → `preview` 看改到的靜態圖 → build → checks，看過改好了才 `resolve --fixed`。 |
| 作者看過審片頁、留言要改 | 不用再審；改得很多（約三分之一以上的分鏡，或整段旁白重寫）才審一輪，只看改過的分鏡。 |

- `review-prep` 自己照這張表選範圍；build 最後印的「下一步」也會照這張表說要不要再審、為什麼。照它做就好。
- 改過的分鏡＝跟上一輪審的那份成片比，分鏡自己的畫面、長度或旁白變了（前面變長、它往後挪不算），加上前一個分鏡換掉的。
  只看改過的分鏡那一輪：素材只做那幾個分鏡（前後各多 1 秒看換鏡），上一輪的問題只帶那幾個分鏡的，審片員通常幾分鐘就看完。
- 為什麼該修不再派審片員：該修不擋出片；改到的分鏡你自己看靜態圖，自動檢查也會重查改過的片段，比再審一輪快得多，作者也看得到改了哪幾張。
- 只看改過的分鏡那種輪次，連續兩輪都還有新的必修：停下來，用口語把問題告訴作者，請他決定改不改。
- 有理由要整支片重看（例如整段旁白重寫、換了聲音，或你懷疑上一輪漏看）：`review-prep <專案> --full`。

## 跟作者怎麼說

- 不用跟作者講 qa、代號這些。講「自動檢查和另一位審片員看過了，下面這幾點我已經改好；這一點想請你決定」。
- 審片頁頂端有「自動檢查」「獨立審片」兩區，每張分鏡卡也列了它自己的問題和處理狀態。
- 作者要關掉獨立審片：`settings set --independent-review 關`（全部影片共用）；要打開：`--independent-review 開`。

## 花多久

在 Danny 的 Mac（10 核）上量的：一支 3 分半、30 多個片段的片，第一次自動檢查約 1 分鐘；什麼都沒改再跑是瞬間（全用快取）；改一個分鏡只重查那一個片段（幾秒）。審片素材整支片約 10 秒、只看改過的分鏡約 5 秒；審片員看一支 2 分鐘的片整支約 9–12 分鐘，只看改過的分鏡通常幾分鐘。作者在等的時候可以先跟他說「機器在檢查，大約一兩分鐘」、「另一位審片員在看，大約十分鐘」。
