# 自動檢查與獨立審片（主 skill 照這份做）

作者打開審片頁之前，這三件事都要做完：**自動檢查**（qa＋字幕帶）、**獨立審片**一輪、處理查出來的**必修**。作者不該當除錯員。

指令一律 `uv run --project ${CLAUDE_PLUGIN_ROOT} python -m article_to_video <子指令> …`，下面省略前綴。直式（9:16）的片每個指令都加 `--aspect 9:16`。

## 順序

1. `build <專案>`：出片（數字對帳、框核對、上一輪沒處理的必修會擋在這裡）。成功時會印「下一步」。
2. `checks <專案>`：自動檢查。每個片段跑 qa、白底片段查字幕帶，結果印出來、寫進審片頁。片段沒變的用快取，改一個分鏡只重查那一個。
3. 處理 checks 的結果（見下）。改了分鏡就回到 1。
4. 獨立審片（使用者設定 `independent_review` 開著才做；`settings show --json` 看）：
   1. `review-prep <專案>`：從成片準備素材，印出 prompt 檔路徑。
   2. 用 Agent 工具派一個 agent，prompt 就是 `prompt.txt` 的全文。它要能跑 Bash（抽幀）和 Read（看圖）。不要把專案的其他資訊塞給它——它只看成片才有意義。
   3. agent 寫好素材資料夾裡的 `review.json` 後：`review-record <專案>`。格式不對會列出哪一項錯，請 agent 改好再記。
5. 處理審片的必修（見下）。改了東西就回到 1；改得多的話再審一輪（4，第二輪會逐條核上一輪）。
6. 都處理完，打開審片頁給作者看（`build`、`checks`、`review-record` 都會更新審片頁）。

## checks 的結果怎麼看

每個分鏡一行：✓ 沒問題、! 該修、✗ 有必修沒處理、? 還沒檢查。有問題的下面列出檢查項目、時間碼、說明、代號，和對照圖（四幀＋運動熱圖，`build/<比例>/checks/qa/<片段>/<片段>.jpg`）。`--json` 或 `build/<比例>/checks.json` 有全部數字。

| 檢查 | 是什麼 | 通常怎麼修 |
|---|---|---|
| 動態 | 圖表幾乎沒在動（沒慢推、畫完就停） | 不要寫 `"push": 0`；或把這段拆短 |
| 跳變 | 一幀裡突然變了一大塊（閃一下） | cue 的 `dur` 太短（例如柱子一幀長完）；拿掉 `dur` |
| 半截字、疊字 | 字被畫面邊緣切掉、兩串字疊在一起 | 推近太多（`push` 調小）、標題或標註太長 |
| 字進字幕帶、字幕帶 | 字或圖壓進燒字幕的那一條 | 推近太多、圖區塞太多東西 |
| 近空白 | 整個畫面幾乎是空的 | 第一個 cue 太晚 |
| 停太久（該修） | 旁白期間超過 5 秒沒有新畫面 | 一句旁白配一個新事件；或拆成兩個分鏡 |
| 確定性、頁面報錯 | 引擎每次渲得不一樣、或報錯 | 回報問題（`report-issue`）給 Danny |

**必修一定要先看對照圖再決定**：真的有問題就改分鏡設定再出片（片段改了會自動重查，不用標）；確定沒問題（例如這裡本來就要一次跳出來）才接受：

```
resolve <專案> qa:SH03:jump@1a2b3c4d --accept "理由"
```

## 獨立審片的必修怎麼處理

- 改得到的就改，改好之後記下：`resolve <專案> R1-2 --fixed "怎麼改的"`。
- 你判斷不用改的，**要問作者**；作者說不改才記：`resolve <專案> R1-2 --accept "作者說…" --by 作者`。不要自己替作者接受審片的必修。
- 該修、可改不擋出片，挑值得改的改；審片頁上作者都看得到。
- 下一輪審片如果說某一項「沒修好」或「部分修好」，那一項會重新變成沒處理。

## 跟作者怎麼說

- 不用跟作者講 qa、代號這些。講「機器檢查和另一位審片員看過了，下面這幾點我已經改好；這一點想請你決定」。
- 審片頁頂端有「自動檢查」「獨立審片」兩區，每張分鏡卡也列了它自己的問題和處理狀態。
- 作者要關掉獨立審片：`settings set --independent-review 關`（全部影片共用）；要打開：`--independent-review 開`。

## 花多久

自動檢查大約是片長的 1～2 倍時間（一支 3 分鐘、30 多個片段的片要幾分鐘；Vox 片段比圖表慢），之後只重查改過的片段。獨立審片素材幾秒鐘；審片 agent 本身看多仔細就多久。
